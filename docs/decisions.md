# Журнал архитектурных решений (ADR)

## ADR-001 — Разделение двух контуров
- **Статус:** принято
- **Решение:** контур разработки (`docs/coordination/`) и контур продуктового агента (`agent/`, `skills/`, `knowledge/`, `projects/`) изолированы; режимы А и Б закреплены в `AGENTS.md`.
- **Причина:** продуктовые ответы не должны утекать служебным контекстом разработки; жюри видит чистый продукт.

## ADR-002 — Пятичатовая координация без внешнего сервера
- **Статус:** принято
- **Решение:** 5 ролей (`Argon-Prime`, `Sonnet-Staff`, `Opus-Core`, `Opus-Mind`, `Argon-Judge`) координируются только через файлы в `docs/coordination/` и Git.
- **Причина:** воспроизводимость, переносимость, отсутствие зависимостей и секретов.

## ADR-003 — Трёхколоночный статус задач
- **Статус:** принято
- **Решение:** у задачи независимые `dev_status`, `audit_status`, `owner_status`; одна строка на `TASK-ID` в `task-board.md`.
- **Причина:** исполнитель, аудитор и владелец не подменяют друг друга; исполнитель не ставит `PASS`/`ACCEPTED`.

## ADR-004 — Append-only журнал handoff с привязкой к коммиту
- **Статус:** принято
- **Решение:** `review-handoff.md` только дополняется; каждая запись содержит `commit_hash` и `agents_md_sha256`.
- **Причина:** аудитор проверяет конкретное состояние кода; история не переписывается.
