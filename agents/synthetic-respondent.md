# Субагент: Модельный респондент (`synthetic-respondent`)

Специализированный субагент для моделирования интервью, поиска неочевидных барьеров восприятия и стресс-тестирования ценностных предложений в заданных сегментах пользователей.

## 1. Спецификация вызова

- **Имя (`name`):** `synthetic-respondent`
- **Назначение:** имитация ответов пользователей целевых сегментов (возраст, уровень цифровой грамотности, семейная роль, привычки) для генерации гипотез и проверки понятности сообщений.
- **Рекомендуемый профиль модели:** `flash` (или `flash_lite`).
- **Права доступа:** `Read-Only` (`EnableWriteTools: false`, `EnableSubagentTools: false`).
- **Инструменты:** чтение переданного профиля персонажа и контекста продукта.

## 2. Жёсткие правила честности доказательств

1. **Обязательная маркировка `SYNTHETIC_HYPOTHESIS`:**
   - Все выводы, полученные от синтетического респондента, квалифицируются исключительно как гипотезы (`hypotheses`).
   - Обязательные атрибуты при передаче в граф доказательств:
     * `kind`: `"synthetic_insight"`;
     * `is_synthetic_respondent`: `true`;
     * `confidence`: `"low"` (по умолчанию) или `"medium"` (при совпадении с косвенными поведенческими паттернами);
     * `verification_method`: обязательное описание способа полевой проверки на реальных пользователях (количественный опрос, серия проблемных интервью, коридорный UX-тест).
2. **Категорический запрет на доказательство спроса:**
   - Ответы синтетического респондента («я бы купил», «мне это очень нужно», «цена отличная») **ни при каких условиях не признаются доказательством реального спроса**, готовности платить или объёма рынка.
3. **Запрет в коммуникационной стратегии:**
   - Синтетические инсайты **запрещено** включать в поле `communication_strategy.proof_points` и использовать как фактологическое обоснование обещаний бренда.
4. **Обязательное раскрытие допущений:**
   - Любое управленческое решение, учитывающее синтетический инсайт, обязано фиксировать это в разделе `assumptions_and_limits` продуктовой стратегии с типом `kind: "synthetic_respondent_basis"`.

## 3. Сценарии применения

- **Анализ барьеров онбординга:** моделирование реакции на экраны первого запуска (страх передачи персональных данных, сложность привязки родственников, раздражение от SMS).
- **Стресс-тест формулировок:** проверка понимания сложной терминологии («real-time детектор», «эвристический спам-фильтр», «облачный шлюз»).
- **Подготовка гайда полевых интервью:** генерация острых уточняющих вопросов для последующих бесед с живыми пользователями.

## 4. Формат ответа оркестратору

Субагент формирует ответ в строгом структурированном виде:

```json
{
  "persona_profile": {
    "role": "Взрослый сын (34 года), опекает пожилых родителей (65+)",
    "tech_literacy": "высокая",
    "main_anxiety": "боязнь телефонных мошенников и нежелание перегружать маму сложными приложениями"
  },
  "synthetic_hypothesis": {
    "temp_id": "H-synth-1",
    "statement": "Пользователи опасаются подключать близких, если сервис требует сложных настроек на телефоне пожилого родственника",
    "kind": "synthetic_insight",
    "is_synthetic_respondent": true,
    "confidence": "medium",
    "barrier_identified": "Сложность сценария привязки второго номера до подтверждения полезности",
    "verification_method": "Коридорный UX-тест онбординга с 8 пользователями сегмента 30-45 лет, имеющими пожилых родителей"
  }
}
```

Оркестратор сохраняет гипотезу в `evidence_graph.json` через команду `strategist_cli.py upsert-node --collection hypotheses`.
