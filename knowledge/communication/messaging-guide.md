# Коммуникационная стратегия: руководство по сообщениям

Справочник для этапа `STRATEGY_DESIGN` (`FR-07`, `T06`). Раздел схемы: `communication_strategy`.

## 1. Аудитория и ситуация (`target_audience_and_context`)

Коммуникация адресуется не «всем», а конкретному человеку в конкретный момент.

Опиши:
- **Кто:** сегмент из `product_strategy.target_audience` (не шире).
- **Ситуация контакта:** где и когда человек встречает сообщение (поиск перед сессией, push в приложении оператора, витрина, рекомендация друга).
- **Состояние:** что он знает о проблеме и о продукте, чем пользуется сейчас.
- **Триггер:** событие, которое делает сообщение актуальным.

Ошибки: аудитория коммуникации не совпадает с аудиторией продукта; ситуация не указана.

## 2. Барьер понимания или выбора (`comprehension_or_choice_barrier`)

Коммуникация снимает один главный барьер. Типы:

| Барьер | Пример | Чем снимается |
|---|---|---|
| Непонимание | «Зачем мне это, у меня есть Excel» | показ задачи и контраста с привычкой |
| Недоверие | «Очередное приложение, бросят» | доказательства, гарантии, бренд |
| Цена переключения | «Переносить данные долго» | импорт, бесплатный старт |
| Неуместность | «Это не для меня» | точный сегмент, кейсы равных |
| Цена | «Дорого за то, что есть бесплатно» | расчёт выгоды, пробный период |

Барьер выбирай по данным (`F-xxx`: отзывы, воронка, интервью); иначе — `H-xxx` с планом проверки.

## 3. Ключевое сообщение (`key_message`)

**Формула:** «Для [аудитория], которые [ситуация/задача], [продукт] — это [категория], который [главная выгода], в отличие от [реальная альтернатива], потому что [доказуемая причина]».

Требования:
- Одна главная мысль; читается за 5 секунд.
- Выгода на языке задачи пользователя, а не функции.
- Контраст с реальной альтернативой (часто — бесплатной привычкой).
- «Потому что» — опирается на `key_capabilities`, а не на прилагательные.
- Ничего из `explicit_refusals`.

## 4. Матрица доказательств (`proof_points`)

Каждое обещание обязано иметь продуктовую опору и доказательство.

| Поле | Требование |
|---|---|
| `promise` | конкретное обещание пользователю |
| `product_capability_ref` | `id` из `product_strategy.key_capabilities` |
| `evidence_refs` | только `F-xxx` / `C-xxx`, подтверждающие обещание |

Правила:
- Без `product_capability_ref` — обещание без продукта, удалить.
- Без `F/C` — обещание без доказательства; переформулировать мягче или перенести в план проверки.
- `H-xxx` с `is_synthetic_respondent: true` **запрещены** в `proof_points`.
- Обычные `H-xxx` в доказательствах не используются; это допущения, раскрываемые в `assumptions_and_limits`.
- Числа в обещаниях — только из `C-xxx` или `F-xxx` с `metric_definition`.

## 5. Проверка непротиворечивости (`consistency_check`, `T06`)

Перед аудитом пройди проверку и запиши результат в `consistency_check`:

1. Каждое обещание связано с `key_capability` выбранного варианта.
2. Ни одно обещание не пересекается с `explicit_refusals` (сверка по смыслу, не только по словам).
3. Нет опоры на синтетических респондентов.
4. Аудитория и барьер совпадают с продуктовой стратегией.
5. Каналы соответствуют ситуации контакта.
6. Сообщение не обещает результат, который не измеряется в `validation_plan`.

Пример конфликта: отказ «не гарантируем повышение оценок» + обещание «поднимите средний балл» → нарушение `T06`.

## 6. Роли каналов (`channels_and_roles`)

Канал выбирается под роль в воронке (`funnel_role`), а не «везде понемногу».

| Роль | Задача | Примеры каналов |
|---|---|---|
| Осведомлённость | узнать о решении | performance, соцсети, медиа экосистемы оператора |
| Рассмотрение | понять ценность | лендинг, обзоры, демо, сообщества |
| Конверсия | начать пользоваться/платить | витрина приложения, onboarding, пробный период |
| Удержание | вернуться и остаться | push, e-mail, in-app подсказки |
| Рекомендация | привести других | реферальная программа |

Для каждого канала: роль, ключевое действие, метрика из `validation_plan`. Собственные каналы оператора (SMS, личный кабинет) — дешёвые, но с риском раздражения: учитывай guardrail «жалобы/отписки».

## 7. Тон и ограничения

- Честность: без превосходных степеней без доказательств («лучший», «№1»).
- Регуляторика: реклама финансовых, образовательных и детских сервисов — осторожно с обещаниями результата.
- Персональные данные не используются в таргетинге без законного основания.

## 8. Чек-лист коммуникационной стратегии

- [ ] Аудитория и ситуация конкретны и совпадают с продуктовой стратегией.
- [ ] Назван один главный барьер, опирающийся на данные или помеченный гипотезой.
- [ ] `key_message` по формуле, с контрастом к реальной альтернативе.
- [ ] Каждый `proof_point` имеет `product_capability_ref` и `F/C`-доказательство.
- [ ] Нет синтетических респондентов и обещаний из `explicit_refusals`.
- [ ] Каналы распределены по ролям воронки.
- [ ] `consistency_check` заполнен по пунктам раздела 5.
