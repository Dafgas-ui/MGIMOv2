# Skill: synthetic-interview

Покрывает п. 59 ТЗ МегаФона («готовить вопросы и проводить беседы с ИИ-собеседниками для поиска гипотез»), `FR-04` (разделение фактов и гипотез), `T06` (proof_points только на фактической базе).

## Когда активировать

- Этап кейса — `EVIDENCE_COLLECTION`: оркестратор решил провести серию синтетических интервью для генерации гипотез.
- Есть хотя бы один открытый `research_question` (Q-xxx), для которого нужна гипотеза о пользовательских барьерах, восприятии или формулировке.
- Эмпирических источников недостаточно или нужен предварительный скрининг гипотез перед полевым исследованием.

## Железные правила честности

1. **Синтетический инсайт ≠ факт.** Результаты попадают ТОЛЬКО в коллекцию `hypotheses` с `kind: "synthetic_insight"`, `is_synthetic_respondent: true`.
2. **Максимальная уверенность — `"medium"`.** Выставляется, только если инсайт совпадает с косвенным поведенческим паттерном из эмпирического источника. По умолчанию — `"low"`.
3. **Запрет доказательства спроса.** Ответы вида «я бы купил», «мне нужно», «цена отличная» не являются доказательством реального спроса, готовности платить или объёма рынка.
4. **Запрет в proof_points.** Синтетические инсайты запрещено включать в `communication_strategy.proof_points` как единственное или основное обоснование.
5. **Обязательное раскрытие.** Если решение учитывает синтетический инсайт, в `product_strategy.assumptions_and_limits` фиксируется запись с `kind: "synthetic_respondent_basis"`.
6. **Обязательный метод верификации.** Каждая гипотеза содержит `verification_method` — конкретный способ полевой проверки на живых пользователях.

## Фаза 1. Подготовка гайда интервью

### 1.1. Сформулировать исследовательский фокус

Выбери 1–3 открытых вопроса Q-xxx из `evidence_graph.json`:

```
python tools/strategist_cli.py resume --case projects/<case>
```

Определи, какие барьеры / точки трения хочешь проверить в интервью.

### 1.2. Составить гайд из 5–7 открытых вопросов

Правила составления:
- **Открытые**, без подсказки ответа: «Расскажите, как вы…», а не «Вы бы купили…?».
- **От общего к частному**: сначала привычки и контекст, затем конкретный продукт.
- **Включить провокационный вопрос**: намеренно предлагать неудобный сценарий для выявления барьеров.
- **Зафиксировать ожидаемый тип инсайта** для каждого вопроса: барьер восприятия, страх, удивление, сомнение.

## Фаза 2. Настройка персоны

### 2.1. Определить социально-демографический профиль

Задай профиль респондента:
- Возраст, семейная роль, город, уровень дохода.
- Уровень цифровой грамотности (`low` / `medium` / `high`).
- Текущий оператор связи, привычки, главная тревога или боль.

### 2.2. Инициировать субагент

Вызови субагент `synthetic-respondent` (описание: `agents/synthetic-respondent.md`):

```
invoke_subagent:
  TypeName: research           # субагент Read-Only
  Role: "Synthetic Respondent"
  Model: flash
  Prompt: |
    Ты — модельный респондент для продуктового интервью.
    ▸ Профиль персонажа: <вставь профиль из 2.1>
    ▸ Контекст продукта: <краткое описание продукта МегаФона>
    ▸ Инструкция: отвечай от лица персонажа, искренне и с сомнениями.
      Если что-то непонятно — говори «Я не понимаю». Если страшно — говори.
      НЕ будь угодливым: нормально критиковать, сомневаться, отказываться.
    ▸ Вопросы интервью:
      1. …
      2. …
```

> **Важно:** субагент запускается с `EnableWriteTools: false`. Он не пишет в граф — это делает оркестратор на Фазе 4.

## Фаза 3. Проведение симуляции диалога

### 3.1. Провести интервью

- Задавай вопросы из гайда последовательно.
- После каждого ответа используй **один** уточняющий зонд: «Почему?», «А если бы...?», «Что вас смущает?».
- Фиксируй дословные цитаты, выражающие барьер или удивление.

### 3.2. Зафиксировать точки трения

По итогам диалога составь список:

| # | Цитата | Тип барьера | Привязка к Q-xxx |
|---|--------|-------------|------------------|
| 1 | «Я не буду ставить приложение маме…» | онбординг / сложность | Q-001 |
| 2 | … | … | … |

## Фаза 4. Экстракция инсайтов и регистрация в графе

### 4.1. Сформировать гипотезу

Из каждой значимой точки трения сформируй JSON-объект гипотезы:

```json
{
  "id": "H-<следующий_номер>",
  "statement": "<Утверждение о барьере / восприятии / поведении>",
  "kind": "synthetic_insight",
  "is_synthetic_respondent": true,
  "depends_on": ["S-<id_источника_контекста>"],
  "confidence": "low",
  "verification_method": "<Конкретный метод полевой проверки: тип, выборка, критерий>",
  "validity_status": "valid"
}
```

Правила заполнения:
- `confidence`: `"low"` по умолчанию; `"medium"` — только при подтверждении косвенным эмпирическим паттерном (указать `depends_on` на F-xxx/C-xxx).
- `confidence: "high"` — **запрещено** для синтетических инсайтов (валидатор выдаст `SYNTHETIC_HIGH_CONFIDENCE`).
- `verification_method`: не «провести опрос», а конкретно — «Коридорный UX-тест онбординга с 8 пользователями сегмента 30–45 лет, имеющими пожилых родителей».

### 4.2. Записать в граф доказательств

```
python tools/strategist_cli.py upsert-node \
  --case projects/<case> \
  --collection hypotheses \
  --payload '{"id":"H-xxx","statement":"...","kind":"synthetic_insight","is_synthetic_respondent":true,"depends_on":["S-xxx"],"confidence":"low","verification_method":"...","validity_status":"valid"}'
```

### 4.3. (Опционально) Зарегистрировать синтетический источник

Если для контекста интервью использовались синтетические материалы, зафиксируй источник:

```
python tools/strategist_cli.py upsert-node \
  --case projects/<case> \
  --collection sources \
  --payload '{"id":"S-xxx","title":"Синтетическое интервью: <роль персонажа>","source_type":"interview","location":"synthetic-interview-session","trust_boundary":"untrusted_data","verification_level":"found","is_synthetic":true,"origin":"synthetic_model","content_hash":null,"version":null,"retrieved_at":null,"notes":"Модельный респондент, flash"}'
```

### 4.4. Залогировать использование ресурсов

```
python tools/strategist_cli.py log-usage \
  --case projects/<case> \
  --step-id synth-interview-<номер> \
  --actor synthetic-respondent \
  --model-tier light \
  --duration-sec <фактическая_длительность> \
  --notes "Интервью с персоной: <роль>"
```

## Фаза 5. Проверка ограничений (Guardrails)

### 5.1. Чек-лист перед завершением

Пройди по каждому пункту — если хоть один не выполнен, исправь перед закрытием фазы:

| # | Проверка | Критерий прохождения |
|---|----------|---------------------|
| 1 | Все гипотезы имеют `kind: "synthetic_insight"` | grep по `evidence_graph.json` |
| 2 | Все гипотезы имеют `is_synthetic_respondent: true` | grep по `evidence_graph.json` |
| 3 | Нет `confidence: "high"` у синтетических гипотез | Валидатор: `SYNTHETIC_HIGH_CONFIDENCE` отсутствует |
| 4 | Синтетические H-xxx не единственные в `proof_points.evidence_refs` | Валидатор: `SYNTHETIC_PROOF_POINT` отсутствует |
| 5 | `verification_method` заполнен конкретно, не шаблонно | Ручная проверка |
| 6 | При использовании в стратегии — `assumptions_and_limits` содержит `kind: "synthetic_respondent_basis"` | grep по `strategy_decision.json` |

### 5.2. Прогнать валидатор

```
python tools/schema_validator.py --case projects/<case> --strict
```

Убедиться в отсутствии ошибок `SYNTHETIC_FLAG_MISMATCH`, `SYNTHETIC_HIGH_CONFIDENCE`, `SYNTHETIC_PROOF_POINT`.

## Антипаттерны (чего НЕЛЬЗЯ делать)

1. ❌ **Записывать синтетический инсайт в `findings`.** Findings — только эмпирические наблюдения с `exact_locator`.
2. ❌ **Ставить `confidence: "high"`.** Максимум `"medium"`, и только с привязкой к реальному F-xxx/C-xxx.
3. ❌ **Использовать как proof_point без реальных доказательств.** `evidence_refs` в `proof_point` должен содержать хотя бы один F-xxx или C-xxx.
4. ❌ **Выдавать «я бы купил» за валидацию спроса.** Синтетический респондент не доказывает ни спрос, ни WTP, ни объём рынка.
5. ❌ **Проводить интервью без привязки к Q-xxx.** Каждое интервью должно отвечать на конкретный исследовательский вопрос.
6. ❌ **Скрывать синтетическое происхождение.** Источник с `origin: "synthetic_model"`, гипотеза с `is_synthetic_respondent: true`.
